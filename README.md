# LectureBot — Telegram → LectureLog

Локальный CLI для Ubuntu 24.04 Desktop. Telegram-бот получает новые файлы из выбранных топиков через Bot API; загрузка идёт под отдельным аккаунтом LectureLog. Пароль Google приложению не передаётся.

Имя программы — **LectureBot**, команда запуска — `lecturebot`. Старое имя команды `lecture-sync` оставлено как совместимый псевдоним.

Если вы уже настраивали первую версию, конфигурация `~/.config/lecture-sync`, состояние `~/.local/state/lecture-sync` и идентификатор записи в связке ключей сохранены намеренно: переименование не сбрасывает авторизацию и историю импорта. Не удаляйте БД состояния. Перед включением нового таймера отключите старый, если он был включён: `systemctl --user disable --now lecture-sync.timer`.

С версии **0.5.0** используется Bot API вместо Telethon. Номер телефона, `api_id`, `api_hash` и сессия основного аккаунта самому LectureBot больше не нужны. Старые настройки Telegram игнорируются; история импорта и вход в LectureLog сохраняются.

**Ограничение для записей лекций:** облачный Bot API скачивает файлы только до **20 МБ**. Для больших файлов поддерживается отдельный локальный Bot API сервер. Его запуск требует `api_id` и `api_hash`: перейти на Bot API и тем самым полностью избавиться от этих данных для больших лекций не получится. Это ограничение Telegram, а не настройка размера в LectureBot.

## Установка на Ubuntu 24.04 Desktop

Склонируйте проект в `~/Projects/LectureBot`:

```sh
sudo apt update
sudo apt install python3-venv gnome-keyring libsecret-1-0
mkdir -p ~/Projects
git clone https://github.com/LectureLog/lecturebot.git ~/Projects/LectureBot
cd ~/Projects/LectureBot
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[browser]'
.venv/bin/lecturebot init
```

Нужна активная графическая сессия пользователя с разблокированным GNOME Keyring и сессионной D-Bus. Сервис запускается **без sudo** от того же пользователя. Для запуска полностью без входа в рабочий стол потребуется отдельная настройка секретов; этот вариант здесь не реализован.

## 1. Telegram

Создайте отдельного бота в [@BotFather](https://t.me/BotFather) командой `/newbot`. Токен вводится скрыто и сохраняется только в GNOME Keyring:

```sh
.venv/bin/lecturebot login-telegram
```

Администратор группы должен добавить бота. Для получения файлов обычных сообщений нужны права администратора либо отключённый privacy mode (`/setprivacy` → Disable в BotFather; после изменения удалите и заново добавьте бота в группу). Права удаления сообщений, блокировки пользователей и управления темами самому LectureBot не нужны. Бот ничего не пишет в группу. Один токен должен использовать только этот экземпляр LectureBot: другой `getUpdates` или webhook конфликтует с получением сообщений. Программа не отключает чужой webhook автоматически.

Bot API не умеет перечислять историю, диалоги пользователя и все существующие топики. ID берутся из приватных ссылок Telegram. Например, для ссылки `https://t.me/c/1234567890/111/222` группа имеет ID `-1001234567890`, топик — `111`, сообщение — `222`. Нужна ссылка с ID топика, а не укороченная ссылка без него.

Укажите **реальные** ID двух топиков в порядке `topic_names` (сначала Сист прога, затем Формалки):

```sh
.venv/bin/lecturebot configure --chat-id -1001234567890 --topic-ids 111 333
```

Числа выше — примеры. `configure` проверяет доступ бота к группе с топиками, но проверить названия старых топиков через Bot API нельзя. Названия в конфигурации — ваши метки предметов.

Если ID неизвестны, после добавления бота отправьте обычное сообщение в нужные топики, затем:

```sh
.venv/bin/lecturebot dialogs
.venv/bin/lecturebot topics
```

Команды получают новые обновления и показывают **только уже наблюдавшиеся** группы/топики. В выводе `topics` название может быть пустым: старые названия Telegram не присылает. Если группа ещё не настроена, сначала используйте `dialogs`, затем `configure --chat-id … --topic-ids …` по ссылкам, либо задайте `chat_id` в конфигурации и используйте `topics`.

### Большие записи: локальный Bot API сервер

Для видео больше 20 МБ требуется [официальный telegram-bot-api](https://github.com/tdlib/telegram-bot-api), запущенный в режиме `--local` на том же Ubuntu. У сервера должны быть свои `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` (либо соответствующие параметры запуска). Сам LectureBot хранит только токен бота. Установка и запуск сервера — отдельный шаг; программа не устанавливает его автоматически.

1. Соберите сервер по [официальной инструкции для своей ОС](https://tdlib.github.io/telegram-bot-api/build.html).
2. Для бота, ранее работавшего в облаке, выполните `logOut` на облачном Bot API перед переходом, как описано в документации сервера. При смене сервера нельзя держать два активных получателя.
3. Запустите сервер с `--local`, слушающий только `127.0.0.1:8081`, с отдельным каталогом данных. Сервер и LectureBot должны иметь доступ к одним файлам, например работать под одним пользователем. Не открывайте этот порт в интернет.
4. В `~/.config/lecture-sync/config.toml` добавьте:

```toml
telegram_api_url = "http://127.0.0.1:8081"
telegram_local_files = "/absolute/path/to/bot-api-data"
```

`telegram_local_files` — реальный корневой каталог файлов сервера. LectureBot принимает абсолютный `file_path` только внутри этого каталога и копирует запись в свою временную папку. Он не удаляет исходный файл из каталога сервера. Другие внешние Bot API адреса не поддерживаются; так токен не отправится на произвольный сторонний сервис.

После настройки сервера выполните `login-telegram`, `configure`, `scan` и пробный импорт. Лимит `max_file_bytes` (по умолчанию 5 GiB) продолжает действовать. При облачном адресе более крупные, чем 20 МБ, записи остаются `pending` с объяснением в `preview`; цикл сообщает об ошибке и продолжает обрабатывать доступные файлы. Увеличение `max_file_bytes` не снимает лимит облака.

Если ранее входили через основной аккаунт, старую сессию можно завершить через Telegram → Настройки → Устройства. LectureBot больше её не использует.

## 2. Вход в LectureLog

Для компьютера с установленным Google Chrome:

```sh
.venv/bin/lecturebot login-web
```

Откроется отдельный временный браузер. Самостоятельно войдите в **отдельный аккаунт LectureLog**. Скрипт сохраняет в GNOME Keyring только `ll_session` сайта; профиль браузера и cookies Google не экспортируются в хранилище инструмента. После проверки доступа браузер закрывается.

Если Chrome не установлен, можно установить Chromium Playwright:

```sh
.venv/bin/playwright install --with-deps chromium
.venv/bin/lecturebot login-web --browser-channel ''
```

Google иногда отказывает во входе через автоматизированный браузер. Поддержан ручной вариант, не требующий Playwright:

```sh
.venv/bin/lecturebot login-web --manual
```

В обычном браузере войдите в отдельный аккаунт LectureLog. Откройте DevTools → Application/Storage → Cookies → **домен LectureLog**, найдите `ll_session` и введите **только её значение** в скрытый локальный запрос терминала. Не копируйте cookies Google, весь заголовок Cookie, HAR или пароль. Значение не передаётся аргументом команды и не попадает в историю shell. При истечении сессии повторите вход.

```sh
.venv/bin/lecturebot check
```

## 3. Просмотр и первый импорт

```sh
.venv/bin/lecturebot scan
.venv/bin/lecturebot preview
.venv/bin/lecturebot import
```

Первый `import` получит временную ссылку от LectureLog и остановится, если хост хранилища ещё не разрешён. Он покажет **только имя хоста**, без секретных параметров ссылки. Проверьте, что это хранилище LectureLog, и внесите точное имя (с портом, если он нестандартный) в `upload_hosts` конфигурации. Затем повторите `import`. Так файл не отправится на произвольный адрес, а cookies LectureLog никогда не попадут в хранилище. Перенаправления при загрузке запрещены.

Пример настройки — не реальный адрес хранилища:

```toml
upload_hosts = ["files.example.org"]
```

Дальнейший единичный запуск объединяет получение обновлений и импорт:

```sh
.venv/bin/lecturebot sync
```

Лекция получает название `предмет — дата — исходное имя [tg…]`. Суффикс связывает её с исходным сообщением и нужен для сверки; не меняйте его до завершения импорта. При загрузке лекции создаются приватными, а после успешной обработки LectureBot автоматически публикует конспекты. `extract_slides = true` повторяет настройку извлечения слайдов; можно отключить в конфигурации.

Скачиваются отдельные файлы поддерживаемых видео/аудиоформатов до 5 GiB. Части записи импортируются отдельными лекциями; PDF, обсуждения и внешние ссылки пропускаются. Временные файлы лежат в `~/.local/state/lecture-sync/downloads` с доступом только владельцу и удаляются после подтверждённого импорта. После сбоя файл сохраняется для повторной передачи.

## Проверка всего пути на одной записи

Можно выбрать конкретное **уже полученное ботом** сообщение Telegram и пройти весь путь: скачать файл, загрузить его в LectureLog, дождаться обработки и опубликовать готовый конспект. Предварительно выполните `login-telegram`, `configure`, `login-web` и настройте `upload_hosts`, как описано выше.

В Telegram скопируйте ссылку **на сообщение с файлом**, а не на сам топик. Пример команды (замените ссылку своей):

```sh
.venv/bin/lecturebot import-one "https://t.me/c/1234567890/111/222"
```

Поддерживаются приватные ссылки `https://t.me/c/CHAT_ID/MESSAGE_ID`, `https://t.me/c/CHAT_ID/TOPIC_ID/MESSAGE_ID`, а также положительный числовой ID сообщения в настроенной группе:

```sh
.venv/bin/lecturebot import-one 222
```

Команда получает доступные обновления в локальную очередь, проверяет соответствие группе и выбранным топикам и импортирует только указанный файл. Bot API не может получить произвольное старое сообщение по ссылке: запись должна быть ранее получена этим ботом и сохранена локально. Если её нет, заново отправьте файл в выбранный топик и используйте новую ссылку. Пересылка в личку боту не импортируется, чтобы не обходить фильтр группы и предметов. Остальные файлы очереди и конспекты не загружаются и не публикуются этой командой. Каждая часть альбома/многосоставной записи выбирается отдельно.

По умолчанию после загрузки команда ждёт готовность до двух часов, проверяя статус каждые 30 секунд. В конце выводится публичная ссылка. Настроить ожидание можно так:

```sh
.venv/bin/lecturebot import-one 222 --timeout 3600 --poll-interval 30
```

При ошибке обработки команда завершается с ненулевым кодом и не публикует конспект. После тайм-аута или прерывания повторите **ту же команду**: подтверждённый импорт не загружается заново, а проверка обработки продолжается. Неоднозначный результат отправки остаётся защищён от повторной загрузки механизмом `reconcile`.

Это явная ручная команда: выбранная запись может быть старше `since`, а её готовый конспект будет опубликован даже при `publish_ready = false`. Дата начала и этот флаг продолжают действовать для автоматического `sync`. Для ручного импорта за пределами `since` после тайм-аута нужно повторить `import-one`: автоматический цикл такие старые записи не подхватит. На время ожидания удерживается общая блокировка приложения, поэтому другой экземпляр LectureBot на этом компьютере не запускается параллельно.

## Автоматическая публикация готовых конспектов

Начиная с версии 0.3.0, `publish_ready = true` включено по умолчанию, в том числе для существующих конфигураций без этого поля. На каждом `sync` бот сначала проверяет ранее импортированные лекции, затем сканирует Telegram и загружает новые файлы. После импорта он ещё раз проверяет незавершённые публикации. С таймером готовые конспекты публикуются на ближайшем цикле проверки (обычно в пределах 30 минут при работающем компьютере).

Чтобы проверить и опубликовать готовые конспекты сразу, без подключения к Telegram и скачивания новых файлов:

```sh
.venv/bin/lecturebot publish-ready
.venv/bin/lecturebot preview
```

Бот использует `GET /lectures/{id}/status`, обновляющий статус обработки. Только при `ready` и приватной видимости он выполняет `POST /lectures/{id}/visibility` с `visibility=public`. Лекции в `processing` и `failed` не публикуются; повторная обработка после ошибки автоматически не запускается. Публичная ссылка сохраняется в поле `public_url` локальной БД и выводится в журнал и `preview`.

Автоматически публикуются только записи, которые есть в локальной БД как `submitted`, имеют ID лекции и относятся к настроенной группе, выбранным топикам и дате начала. Другие лекции аккаунта не публикуются. Это распространяется и на ранее импортированные ботом записи: старая БД обновляется автоматически, история импорта сохраняется. Явная команда `import-one` может выбрать запись старше даты начала, как описано выше.

При потере ответа на публикацию следующий запуск проверяет текущую видимость на сайте. Если лекция уже публичная, повторный запрос не отправляется. Сам запрос устанавливает `public`, а не переключает видимость, поэтому повтор не скроет конспект и не создаст новую задачу обработки. Завершённые публикации запоминаются; если вы впоследствии вручную скроете такую лекцию, бот не будет автоматически публиковать её заново.

Для отключения будущих публикаций добавьте в `~/.config/lecture-sync/config.toml`:

```toml
publish_ready = false
```

Это не скрывает конспекты, уже опубликованные ранее.

## 4. Автоматическая проверка каждые 30 минут

Включайте расписание после успешного первого импорта:

```sh
mkdir -p ~/.config/systemd/user
cp deploy/lecturebot.service deploy/lecturebot.timer ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now lecturebot.timer
systemctl --user list-timers lecturebot.timer
journalctl --user -u lecturebot.service -n 50
```

В unit указан путь `~/Projects/LectureBot/.venv/bin/lecturebot`; исправьте его, если разместили проект иначе. `init` заранее создаёт каталог состояния. При нестандартном `XDG_STATE_HOME` задайте одинаковое окружение интерактивному запуску и unit. Таймер пользовательский, зависит от доступности графической сессии и разблокированного GNOME Keyring. Это не фоновый сервис с автономным доступом к секретам после перезагрузки без входа пользователя. Unit не требует привилегированных mount namespaces; отключены core dumps, установлен `UMask=0077`.

Остановить расписание:

```sh
systemctl --user disable --now lecturebot.timer
```

## Неоднозначные загрузки и дубли

Состояния: `pending → confirming → submitted`; при сбое после отправки confirm — `uncertain`. `submitted` означает, что LectureLog принял лекцию, а не что конспект уже готов. Повторная обработка не запустится автоматически даже при HTTP 500 на confirm: сервер мог уже создать задачу.

```sh
.venv/bin/lecturebot reconcile
.venv/bin/lecturebot preview
```

Сверка ищет точный заголовок в «Моих лекциях». Если запись найдена однозначно — помечает импорт завершённым. Если её нет, автоматический повтор остаётся заблокированным: отсутствие карточки не гарантирует отсутствия задачи в ядре. Только после ручной проверки, что задача не создана:

```sh
.venv/bin/lecturebot resolve 12345 --confirmed-absent
.venv/bin/lecturebot import
```

Защита действует для пары `(chat_id, message_id)` при сохранности локальной БД и заголовков на сайте. Глобальная гарантия exactly-once невозможна без серверного ключа идемпотентности. Разные сообщения с одним и тем же видео считаются разными записями. Удаление БД, переименование заголовков или одновременный запуск на разных компьютерах могут нарушить сверку. На одном компьютере параллельный запуск блокируется файловой блокировкой.

## Безопасность и ограничения

- Секреты хранятся только в GNOME Keyring (на macOS для разработки допускается системный Keychain). Не используется plaintext fallback. Доступ приложений под тем же Unix-пользователем к разблокированной связке ключей остаётся риском.
- Отсутствуют Google-пароли, cookies Google и токен Telegram-бота в конфигурации, БД и логах. В БД сохраняются ID бота, группы, топика и сообщения, метаданные файлов и Bot API file_id; тексты сообщений и подписи не сохраняются. Сам код не включает предоставленные в переписке учётные данные.
- HTTPS проверяется штатно. Окружение прокси и `.netrc` не используются. При необходимости прокси потребуется отдельная настройка.
- При `publish_ready = true` бот публикует успешно обработанные конспекты, относящиеся к его импортам. Он не удаляет лекции и не обращается к административным настройкам. Однако cookie аккаунта LectureLog даёт все штатные права этого аккаунта.
- Развёрнутый сайт может отличаться от проверенного кода. Изменение формата страниц или API приводит к остановке, а не обходу защиты.
- Пока проверено локальными тестами с имитацией сервисов. Реальные вход, Telegram и загрузка в работающий LectureLog требуют настройки на вашем Ubuntu.

Проверенный контракт: LectureLog `dev`, commit `b6c040ea90e993f2c6f7e11c3df124d968c7223b`: `POST /upload/presign`, отдельный `PUT`, `POST /upload/confirm`, `GET /lectures/{id}/status`, `POST /lectures/{id}/visibility`, session cookie `ll_session`, CSRF из `GET /upload`.

Обновление ранее установленного LectureBot:

```sh
cd ~/Projects/LectureBot
git pull --ff-only
.venv/bin/python -m pip install -e '.[browser]'
.venv/bin/lecturebot publish-ready
```

После обновления выполните `login-telegram` для нового токена BotFather и проверьте числовые ID группы/топиков. Не удаляйте старую БД: она сохраняет защиту от повторной загрузки. Старые незагруженные записи потребуют повторной отправки файлов в Telegram: у Bot API нет их `file_id`. Уже загруженные лекции продолжают проверяться и публиковаться без повторного скачивания.

Менять установленный таймер не требуется: он запускает `sync`, включающий проверку публикаций.

Обновления Telegram хранятся **не дольше 24 часов**. Компьютер должен регулярно получать их; простой более суток может привести к пропускам. Метаданные файлов и offset сначала сохраняются одной транзакцией SQLite, а потом подтверждаются Telegram следующим запросом. Если процесс упал после сохранения, очередь восстанавливается при следующем запуске. Не запускайте получателей одного токена на двух компьютерах. `scan --history` завершается с объяснением ограничения вместо имитации чтения истории.

Тесты:

```sh
.venv/bin/python -m unittest discover -s tests -v
```
